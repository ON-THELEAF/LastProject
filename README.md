# BridgeDocs — 개인정보 문서용 오프라인 AI 문서처리 프로그램 (졸업작품)

부동산·학교·병원·주민센터·은행처럼 개인정보가 들어 있는 문서를 많이 다루는 기관을 위한 **Windows 데스크톱 프로그램**이다. PDF·이미지·docx 문서의 값을 AI로 읽고, AI가 잘못 읽었을 수 있는 칸만 사람이 확인한 뒤 엑셀·CSV·txt로 내보내거나 기존 파일에 누적한다. 기본 문서 작업은 인터넷 없이 사무실 PC 한 대(그래픽카드 메모리 12GB 이상, 예: RTX 3060 12GB)에서 돌고, 문서와 결과는 PC 밖으로 나가지 않는다. 화면은 웹(React)으로 만들어 이 PC 안(127.0.0.1)에서만 열고 Edge 앱 창으로 띄운다.

## 기능 현황 (기능명세서 기준)

| 기능명세 | 내용 | 상태 |
|---|---|---|
| REQ-001 홈 화면 | 위쪽 메뉴(홈·문서 읽기·문서 만들기·문서 관리), 파일 놓는 곳, 작업 고르기 카드, 워드 양식 관리 | ✅ 구현 (문서 만들기는 "준비 중") |
| REQ-003 문서 읽기 | 파일 넣기·대기열·취소, 읽는 길 자동 선택(PDF 글자·OCR·docx), 문서 종류 판별, **A경로**(등록 양식: PaddleOCR 한국어) / **B경로**(처음 보는 양식: Qwen3-VL-4B), 사용자 양식 저장 | ✅ 구현 (읽기 전 칸 고르기·저장된 결과 다시 열기/삭제는 미구현) |
| REQ-002 환각 검증·사람 확인 | OCR 힌트 없이 한 번 더 읽어 비교 + 실제 페이지 글자 대조 + 확대 재판독 → 통과한 칸만 자동 확정, 나머지 "확인 필요". 확인 화면에서 확정·비교 값 적용·되돌리기·한 번에 확정 | ✅ 구현 |
| REQ-004 내보내기 | 엑셀·CSV·TXT, 새 파일 / 기존 파일에 이어 붙이기, 여러 문서 한 파일로, 확인 필요 칸 남으면 경고 | ✅ 구현 |
| REQ-006 설치·업종 설정·로컬 처리 | 인터넷 없이 로컬 처리, 모델은 PC 안 `models\`에서만 | ✅ 구현 (첫 실행 업종 선택·테마는 미구현) |
| REQ-007 표 데이터로 문서 만들기 | 표 데이터를 워드 양식 빈칸에 채워 여러 문서 생성, PDF·PNG 저장 | ⏳ 향후 (2026-11-25 엔진·서버에서 걷어냄, 화면은 "준비 중"으로 막음) |
| REQ-008 온라인 문서 진위 확인 | 인터넷 연결·문서별 동의 시에만 필요한 칸 값을 발급기관 조회로 확인하고 즉시 삭제, 로컬 검증 결과와 분리 표시 | ⏳ 향후 |

**정책:** 기본 작업은 PC 밖으로 문서·결과를 보내지 않음(POL-001) · 확인 필요 칸이 남으면 내보내기 전 사람 확인 우선(POL-002) · 고쳐도 처음 읽은 값 보존(POL-003) · 오류는 화면에 그대로 보여 줄 수 있는 한국어 문장(POL-004)

**핵심 지표 (PRD):** 필드 정확도 70% 이상 · 문서 20건 10분 이내 · GPU 메모리 12GB 이내 — 실제 서류로는 아직 측정 전

## 실행

- **팀원 PC 처음 한 번:** Git·Python 3.11·Node.js를 깔고 `git clone https://github.com/ON-THELEAF/LastProject.git` → `BridgeDocs 설치.bat`(패키지 설치·화면 빌드·AI 모델 약 9GB 받기, 모델은 git에 안 올라감)
- **그다음부터:** `BridgeDocs 실행.bat`만 누른다. 켤 때마다 GitHub에서 최신 코드를 받고(`git pull`), 바뀐 게 있으면 패키지·화면을 다시 빌드한 뒤 실행한다. 내 수정을 팀원에게 주려면 커밋하고 `git push`.
- 소스로(GPU PC): `BridgeDocs 실행.bat` 또는 `python SERVER\web_app.py` (먼저 `Front` 폴더에서 `npm install` → `npm run build`로 `Front/dist/`를 만든다. 화면을 고치면 다시 `npm run build`)
- 엔진만 명령줄로: `python Fuc/bridgedocs.py run 문서.pdf …` — [`Fuc/README.md`](Fuc/README.md)

## 시스템 구조

```
화면 Front/  →  서버 SERVER/(web_app·web_api·service)  →  기능 Fuc/(bridgedocs.py가 입구)  →  저장 DB/ · 모델 models/
```

| 단계 | 하는 일 |
|---|---|
| **1. 문서 입력** | PDF·이미지·docx 받기 → 쪽 이미지로 바꾸기 → 스캔본 기울기 보정 → 문서 종류 판별(처음 보는 종류는 새 종류) |
| **2. 문서 분석** | **PDF 안 글자**(믿을 수 없는 쪽만 OCR) · **OCR**(PaddleOCR 한국어 모델) · **docx 글자** 중 자동 선택. 등록 양식은 **A경로**(정해진 칸), 처음 보는 양식은 **B경로**(AI가 칸을 골라 추출 → 칸 이름을 사용자 양식으로 저장). 읽은 줄을 힌트로 AI(Qwen3-VL-4B)에게 칸마다 질문 |
| **3. 환각검증·사람 확인** | 형식·페이지 글자 대조, OCR 없이 다시 읽기, 이름·숫자 칸 확대 재판독 → 자동 확정 / 확인 필요. 문서 읽기 탭에서 칸을 누르면 문서 위에 상자(노랑 = 확정, 빨강 = 확인 필요) |
| **4. 내보내기** | 엑셀·CSV·txt 저장(이어 붙이기 가능). 문서마다 결과 JSON은 읽을 때 바로 저장 |

**문서 만들기:** 2026-11-25에 엔진·서버에서 걷어냈고, 화면은 "준비 중" 안내로 막아 둠(`make.tsx`는 다시 붙일 때 씀). 기능명세 REQ-007대로 다시 구현할 예정.

## 폴더

| 폴더/파일 | 내용 |
|---|---|
| `Front/` | 화면. `src/`(피그마 메이크 코드 기반): `App.tsx`(홈·위쪽 메뉴), `reader.tsx`(문서 읽기·결과 확인·내보내기), `make.tsx`(문서 만들기 1~3단계, 지금은 쓰지 않음), `documents.tsx`(문서 관리), `ui.tsx`(공통 모양), `api.ts`(엔진 부르기). `dist/`는 `npm run build` 결과(저장소에 안 올림) |
| `SERVER/` | 서버: `web_app.py`(이 PC 안 서버·Edge 앱 창), `web_api.py`(화면 버튼 ↔ DesktopService), `service.py`(엔진의 유일한 입구), `worker.py`(읽기 작업 스레드), `offline.py`(인터넷 차단·모델 위치·설정.json), `INTERFACE.md`(약속), `requirements.txt` |
| `Fuc/` | 기능: `bridgedocs.py`(입구·명령줄) 아래 기능별 폴더 — `path_a_ocr`(A경로 OCR), `pdf_text`(PDF 안 글자), `docx_read`(docx 글자), `path_b_vlm`(B경로 AI 질문), `hallucination_check`(환각검증·재판독), `read_pipeline`(문서 읽기 전체 흐름·종류 판별·기울기 보정), `view`(결과 보기 HTML), `export`(판정·내보내기), `make_doc`(문서 종류 표기·표 파일 읽기·워드 양식 빈칸 찾기 도우미), `scoring`(정답 비교) |
| `DB/` | 저장·불러오기: `기본 양식.json`(기본 문서 양식: 종류·칸·칸 종류·AI 질문·검사 규칙. 코드에는 양식이 없음), `forms.py`(양식 불러오기·사용자 양식의 칸 종류 짐작), `storage.py`(새 문서 종류 목록 JSON, 워드 양식 폴더, 결과 JSON 다시 저장) |
| `models/` | AI 모델(약 9GB, 저장소에 안 올림) |

## 설치할 때 정하는 폴더

프로그램 옆에 `설정.json`을 두면 워드 양식 폴더와 저장 폴더(읽기 결과 JSON·내보내기)를 바꿀 수 있어요. 없으면 양식은 프로그램 옆 `양식\`, 저장은 `문서\BridgeDocs 결과`예요.

```json
{"양식 폴더": "D:/사무소/양식", "저장 폴더": "D:/사무소/결과"}
```

- 필요 사양: 그래픽카드 메모리(VRAM) 12GB 이상.
