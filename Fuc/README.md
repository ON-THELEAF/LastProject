# Fuc — 읽기·검증 엔진(기능별 폴더, 입구는 bridgedocs.py)

문서 이미지·PDF·docx에서 필드를 읽고(A경로 OCR, B경로 VLM, PDF 글자 레이어, docx 글자), 환각검증으로 의심 값을 골라내는 코드가 **`bridgedocs.py` 파일 하나**에 모두 들어 있다.

## 시스템 구조 (2026-10-24 확정)
```
python bridgedocs.py run 문서1.pdf 문서2.docx 스캔_p1.png 스캔_p2.png [--deskew] [--out 결과]
```
| 단계 | 하는 일 |
|---|---|
| 1. 문서 입력 | PDF·이미지·docx 받기(`X_p1.png, X_p2.png`는 한 문서), 쪽 이미지(150dpi)로 바꾸기, 스캔본 기울기 보정(`--deskew`), 문서 종류 판별(부동산 5종 + 자격증·수료증·성적증명서) |
| 2. 문서 분석 | 읽는 길을 문서마다 자동으로 고른다: **PDF 안 글자**(쪽마다 믿을 수 있는지 진단, 아니면 그 쪽만 OCR) · **OCR**(이미지·스캔) · **docx 글자**(이미지 없이). OCR은 한국어 모델 하나만 쓴다. 그 글자 줄을 힌트로 AI(Qwen3-VL)에게 칸마다 질문 |
| 3. 환각검증 및 사용자 판별 | 규칙 검사 · 주소 두 번째 판독 · 이름·기관 칸 **확대 재판독**(한 획 차이) → 자동 확정/확인 필요. 결과보기.html이 브라우저로 열리고, 쪽 이미지 위 색 상자·표·개수 요약을 보며 "확인 필요" 칸을 후보 버튼이나 직접 입력으로 판별(처음 읽은 값도 남김) |
| 4. 데이터 추출 | 화면의 [내보내기] 창에서 엑셀·CSV·JSON 중 골라 내려받기(xlsx도 라이브러리 없이 브라우저에서 만듦) |

**문서 만들기:** 2026-11-25에 지웠다(`make` 명령 없음).

결과 폴더(`--out`, 기본 `결과/`)에는 문서별 결과 JSON과 `결과보기.html`이 남는다. 화면을 다시 열려면 `결과보기.html`을 더블클릭한다.

## 명령
`python bridgedocs.py <명령> [옵션]` — 명령마다 옵션은 `--help`로 본다.

| 명령 | 하는 일 |
|---|---|
| **`run <파일...>`** | **위 1~4단계 전체.** `--out 폴더`, `--deskew`, `--no-open`(브라우저 안 열기) |

### 문서 종류와 읽는 칸
| doc_type | 문서 | 칸 |
|---|---|---|
| `registry` | 등기사항전부증명서(집합건물) | 소재지, 현재 소유자, 소유권 접수일, 압류 여부, 채권최고액, 근저당권자 |
| `lease` | 주택임대차 표준계약서 | 임대인, 임차인, 보증금, 차임, 시작일, 종료일 |
| `sale` | 부동산 매매계약서 | 매도인, 매수인, 매매대금, 계약금, 잔금일, 인도일 |
| `ledger` | 집합건축물대장(전유부) | 대지위치, 소유자(공유면 `이름(지분), …`), 소유권 변동일, 주 용도, 전용면적, 위반건축물 여부 |
| `store_lease` | 상가건물 임대차 표준계약서 | 임대인, 임차인, 보증금, 차임, 관리비, 시작일, 종료일 |
| `cert` | 자격증·수료증·성적증명서(한국어·영어) | 증명서 종류, 이름(원문 글자 그대로), 자격·시험·과정, 등급·점수, 발급기관, 취득일, 증명서 번호, 문서 언어(엔진이 판별) |

- 건축물대장(2026-10-25 실제 발급본 5건 확인 후 수정): 정부24 전유부에는 **사용승인일 칸이 없어서**(표제부에만 있음) 전용면적으로 바꿨다. 소유자현황은 이력이 아니라 **현소유자만** 표시되며, 여러 줄이면 공유다(지분 합이 1이어야 함).
- 증명서는 양식이 기관마다 달라 칸 좌표·라벨 검사 대신 **값이 페이지 글자에 그대로 있어야** 한다(없으면 확인 필요). 영문 월 이름 날짜도 알아보고, 시험별 점수 범위(TOEIC 10~990, IELTS 0~9, TOPIK 1~6급)를 벗어나면 확인 필요.

## 엔진 결과 형식 (`run` / `process_document()`)
서버·화면은 이 형식을 그대로 쓴다.
```json
{"source": ["매매.pdf"], "route": ["pdf_text"], "doc_type": "sale", "pages": 1, "summary": {"auto": 5, "review": 1},
 "fields": [{"key": "buyer_name", "label": "매수인", "kind": "name", "value": "강해숙", "status": "auto",
             "reason": "", "candidates": [], "page": 1, "line_box": [x0, y0, x1, y1]}]}
```
- `route`: 쪽마다 읽은 길 — `pdf_text`(PDF 안 글자) / `ocr` / `docx`. docx는 쪽 이미지가 없어 `line_box`가 없고 두 번째 판독도 하지 않는다.
- `status`: `auto`(자동 확정) / `review`(사람 확인). `reason`에 확인이 필요한 이유, `candidates`에 고를 후보(읽은 값, 두 번째 판독 값).
- 화면에서 판별하면 `review`가 `confirmed`(읽은 값·후보 선택) 또는 `edited`(직접 입력)로 바뀌고, 처음 읽은 값은 `read_value`에 남는다(내려받은 JSON 기준).
- CSV·엑셀은 한 줄에 칸 하나: `파일, 문서 종류, 항목, 값, 상태, 처음 읽은 값, 확인 사유, 쪽` (문서 종류가 섞여도 같은 열).
- 검증 = 규칙 검사 + **두 번째 판독**: 주소는 OCR 줄 없이 한 번 더 물어 두 답이 다르면 확인. 이름·소유자·발급기관은 **그 칸만 3배로 확대해 다시 읽고**(OCR 오독을 AI가 따라 쓴 경우: 굿타임→곳타임), 한글은 **자모 하나 차이(한 획 정도)**, 외국어 이름은 다르면 사용자 판별. 후보 버튼에 다시 읽은 값·연도를 바로잡은 날짜·지분을 짝지은 소유자를 낸다.
- **값을 페이지 글자에서 못 찾으면 사람 확인**(2026-10-25부터). 예전엔 OCR이 놓쳤을 수 있다고 통과시켰는데, 오류 주입 시험에서 한 글자 틀린 금액·날짜·주소·이름이 모두 이 길로 자동 확정됐다. 양식 밑줄('_2025_년')과 표 칸 줄바꿈은 찾은 것으로 본다.
- 측정(2026-10-25, 처음 보는 시드의 합성 문서 · 오류 주입 = 문서마다 AI 첫 답 하나를 그럴듯한 틀린 값으로 바꿔 치고 잡는지 확인):

| 대상 | 칸 | 자동 확정 중 틀림 | 괜한 확인 | 오류 주입 ① 그럴듯한 틀린 값 | 오류 주입 ② 잘림·다른 칸 값·종류 착각·'없음' |
|---|---|---|---|---|---|
| 증명서 거친 스캔 33건(중·일 포함, 2026-11-08에 중·일 지원을 빼기 전) | 264 | 0 | 5 | 32/32 (띄어쓰기만 다른 1건 제외) | 33/33 |
| 부동산 5종 20건 | 124 | 0 | 5 | 20/20 | 20/20 |
| 실제 건축물대장 5건 | 30 | 0 (틀린 1칸은 확인 필요 + 정답 후보) | 0 | — | — |

  - 오류 주입 ②는 superpowers 코드 리뷰(2026-10-25)가 지적한 유형이다. 처음 돌렸을 때 증명서에서 25/33만 잡았다. 놓친 것은 이름 칸에 같은 문서의 다른 칸 값(발급기관·시험명)을 넣은 경우 6건과 증명서 종류 착각 2건이었다. 지금은 아래 규칙으로 모두 잡는다.
    - 증명서 이름 칸끼리 값이 같으면 확인
    - 증명서 종류는 제목 줄의 낱말로 확인
    - 더 긴 이름의 일부(김민 ⊂ 김민준)면 확인
    - 건축물대장 변동일은 '소유권…' 줄 근처의 가장 최근 날짜, 면적은 '공용부분' 위만 인정
  - "놓친 오류 0"은 **시험한 오류 종류 안에서 0**이라는 뜻이다. 합성 문서는 같은 생성기로 만들어 실제보다 쉽다. 실제 증명서·계약서로는 아직 재지 않았다.
- 크롭 재질문은 쓰지 않는다(2026-10-24 실험: 검출 이득 없이 오탐만 늘어남).
- 처리 시간: 문서 1건 약 10초(RTX 4070 SUPER).
- GPU 메모리(2026-10-25 실측, 지금은 빠진 중·일 OCR까지 띄운 상태, RTX 4070 SUPER 12GB): 증명서와 부동산을 연달아 처리할 때 최대 **10.9GB / 12.3GB**(화면 등 기본 사용 0.5GB 포함). 12GB 카드에서 여유는 약 1.4GB.

## 샘플 폴더 형식
`b`, `a` 명령은 `--samples <폴더>`를 받는다. 폴더에는 쪽 이미지(png)와 `ground_truth.json`이 있어야 한다.
```json
{"문서이름": {"doc_type": "sale", "pages": ["문서이름_p1.png"],
  "fields": {"buyer_name": {"value": "정답 값", "kind": "name", "page": 1, "region": null, "b_skip": false}}}}
```
`region`(칸 좌표)은 A경로 칸 읽기에만 필요하다. 정답 값은 샘플을 만들 때 넣은 값을 그대로 쓰면 된다.

## Windows GPU 환경 (RTX 4070 SUPER 12GB에서 확인)
A경로(PaddleOCR)와 B경로(VLM)를 같은 GPU에서 돌린다. 가상환경은 프로젝트 **밖** `%USERPROFILE%\.venvs\bridgedocs` 에 둔다(파일이 수만 개라 프로젝트 안에 두면 변경 목록이 넘친다).
```bash
py -3.11 -m venv %USERPROFILE%\.venvs\bridgedocs
set P=%USERPROFILE%\.venvs\bridgedocs\Scripts\python
%P% -m pip install paddlepaddle-gpu==3.3.1 -i https://www.paddlepaddle.org.cn/packages/stable/cu126/
%P% -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu126
%P% -m pip install paddleocr==3.7.0 pymupdf==1.28.2 pillow==12.3.0 transformers accelerate
%P% -m pip install nvidia-cudnn-cu12==9.10.2.21   # torch와 cuDNN 버전을 맞춤(pip 경고는 무시)
```
- torch와 paddle이 이름이 같은 CUDA DLL을 따로 갖고 있어서, **torch를 먼저 불러와야** 둘 다 동작한다. `bridgedocs.py`가 Windows에서 자동으로 그렇게 한다.
- 한글 출력이 깨지면 `set PYTHONIOENCODING=utf-8`.
- B경로는 `--dtype bfloat16`으로 돌린다(4070은 bf16 지원).
- 입력이 약 4,400토큰을 넘으면 GPU 메모리(화면이 약 2GB 사용)가 넘쳐 매우 느려진다. `docx` 명령은 긴 문서를 자동으로 줄인다.
